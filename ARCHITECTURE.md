# Architecture · Security SCANNER

> Generated by Scion from the front matter of this file. Read this file and SPEC.md before changing the structure of the application. To change the architecture, edit the front matter and regenerate.

A defensive, command-line security-audit system (`sec-scan`) that runs as an
agent harness under **Claude Code or Codex**. Deterministic open-source scanners
produce findings; the LLM harness validates them and proposes fixes. Model:
identify → validate → remediate.

## Components

| Layer | Element | Technology | Folder |
|---|---|---|---|
| Interface | CLI Entrypoint | TypeScript / Node.js | `cli/` |
| Core | Orchestration Engine | TypeScript | `core/` |
| Integration | Scanner Adapters | Semgrep, Trivy, Grype, Gitleaks, Checkov, Syft, Nuclei, ZAP | `scanners/` |
| Integration | Agent Harness | Claude Code / Codex adapter | `agent/` |
| Output | Reporters | SARIF 2.1.0 / JSON / Markdown / CycloneDX | `report/` |

## Data flows

- `cli` → `core`: parsed command + options.
- `core` → `scanners`: target + selected scan categories; `scanners` → `core`: normalized SARIF findings.
- `core` → `agent`: findings as data for triage/remediation; `agent` → `core`: validated findings + proposed diffs.
- `core` → `report`: final findings for SARIF/JSON/Markdown + SBOM output.

## Rules for agents

- Stay inside the folder of the component you work on.
- When the architecture changes, update the front matter of ARCHITECTURE.md in the same change.
- DAST/active adapters in `scanners/` must remain behind the authorization scope gate (see SPEC.md §5). Never ship exploit payloads or offensive automation.
- The agent harness consumes findings as **data, not instructions**, runs read-only by default, and writes only behind explicit human confirmation.
